## Implementation report

1. **Kilogram graphs:** Bodyweight previously filtered out readings whose stored unit differed from the preference; Strength relabeled stored pounds without conversion. Readings now normalize copied display data before graphing and averaging. Strength reads per-set provenance, with legacy missing units treated as pounds as explicitly confirmed by the account owner. Switching preference never rewrites activity.
2. **Units:** lb ? kg uses 0.45359237; kg ? lb uses 2.2046226218. Same-unit labels preserve their recorded numeric value; converted labels show up to four decimals. PR comparisons use kilograms rounded to six decimals (a 0.000001 kg comparison grid), separately from display rounding. SQL uses the same grid. No estimated strength or estimated 1RM exists. Existing edits retain their original unit and raw form numbers; newly saved sets record their entered unit. Bodyweight averages normalize before calculating.
3. **Schema:** New groups, group_members, group_invites tables, indexes and four group RPCs plus a membership helper. One nullable strength_sets.weight_unit column supplies future unit provenance without a default or backfill. The existing invoker save_strength_workout RPC now records units on new sets and leaves existing units unchanged. No migration statement updates existing activity rows; updates/deletes inside the save function remain explicit user-edit behavior.
4. **Privacy:** All three tables enable RLS. Authenticated users can directly select only group ID/name/timestamps, subject to membership. No direct membership/invite reads or writes are granted. A nonrecursive SECURITY DEFINER membership helper uses auth.uid(). Group RPCs have empty search paths, no anonymous/public execution, and server-side membership/ownership checks. Summaries expose opaque membership handles, chosen display names, roles and aggregate totals only. No cross-account raw sets, notes, locations, Bodyweight, email or auth metadata are returned. Existing activity RLS/ownership constraints stay intact. Owner actions and aggregate reads coordinate through group locks; each subsequent RPC checks current membership. Already-rendered summaries refresh on focus/every 30 seconds; revocation cannot erase information already seen.
5. **Invites:** Explicit Create/Join forms require a chosen non-email display name and sharing consent. No automatic enrollment. Owners generate two random UUIDs joined into a 64-character code (244 random bits); only its SHA-256 hash is stored. Links carry the token in the fragment. Rotation revokes earlier codes; invites expire in seven days and permit 100 new joins. The join transaction checks revocation, expiry and capacity under locks. Owners can rename, remove members, revoke and delete; members can leave. Owners cannot remove themselves or leave an ownerless group. Group deletion affects only group metadata.
6. **Strength:** Each actual saved set counts once toward its primary muscle group. Repetition and distance sets both count. Compound tags do not multiply counts. Stacked horizontal bars have member controls and accessible count text. Calendar week starts Monday; month is month-to-date; three/six-month periods include the current month; year starts January 1 in the viewer's named timezone. Monthly PR races always use the named current month, regardless of the set-period selector, and establish truth using all earlier actual sets. First workouts are excluded, Weight PR takes precedence over Rep PR, and equal-weight Rep PR uses the canonical grid. Ties use competition ranks and stable name/ID ordering.
7. **Cardio:** Activity names normalize whitespace/case. Duration sums exact stored seconds. Compatible metres/km/miles/yards/feet normalize to metres; missing or unsupported distance stays null and is unranked. Ranking rows show duration, distance, entry count and activity. All-compatible and per-activity views are available.
8. **Navigation:** Mobile shows Home, Strength when enabled, Progress, Leaderboards, More. More contains enabled Cardio/Flexibility/Bodyweight plus Settings. At most five bottom destinations. Desktop retains all destinations. Routes include /leaderboards and browser Back retains normal routing behavior.
9. **Controls:** Graph Mode is a non-searchable custom dropdown. Primary selectors use dark text/borders, while compact Chart Controls remain secondary. No native select/alert/confirm/prompt introduced.
10. **Colors:** Rep PR is blue throughout, Weight PR remains green, First Entry neutral. Your Sets now uses red, green, blue, black, orange, purple and teal with labeled counts.
11. **Announcement:** Final identity is progressive-overload-2.0-launch, using existing migration 008 acknowledgement storage. Private Groups and competition lead; Explore 2.0 and View Leaderboards actions are available. It waits for account readiness and other dialogs, supports Settings ? What?s New, and respects reduced motion. Manual reopening does not rewrite acknowledgement rows. Failed persistence is nonblocking with session fallback.
